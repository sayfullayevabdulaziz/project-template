# Mobile (Flutter end-user app) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build `template/mobile/`, the Flutter end-user app of the project template: register, login, session restore, paginated published-items list and detail, against the backend's `/api/v1` public surface.

**Architecture:** Official Flutter architecture guide. UI layer = screens + Riverpod 3 `Notifier`s as view models (no codegen). Data layer = services (wrap the swagger_parser-generated retrofit clients, map DTOs to domain types) + repositories (policy: tokens, error mapping, pagination). The riskiest logic, the dio auth interceptor (single-flight refresh), is dependency-free (talks to a `TokenStore` interface and a refresh callback) so it is tested with hand-written fakes and a fake `HttpClientAdapter`. Generated DTO symbols are touched in exactly three files (`auth_service.dart`, `user_service.dart`, `items_service.dart`) so a symbol-name correction is a one-file edit.

**Tech Stack:** Flutter 3.47 / Dart 3.13, flutter_riverpod 3.4, go_router 18, dio 5.11, retrofit 4.10, swagger_parser 1.45 (json_serializable), flutter_secure_storage, flutter_lints, flutter_test + integration_test (no mocking library).

**Spec:** `docs/superpowers/specs/2026-10-20-project-template-design.md` (sections 3, 4, 5, 6.3, 6.6 to 6.10, 8 matter most). Acceptance criterion 5.

## Review Focus

1. Concurrent requests all get 401 and the refresh itself returns 401: session must expire exactly once, every caller fails, no request is retried (Task 4).
2. Refresh fails transiently (offline, 5xx, 429): the user must NOT be logged out and tokens must stay (Task 4).
3. Pagination edge cases: item deleted between pages (duplicate/shifted rows), empty page while `total` still larger (infinite loop), double `loadMore` while loading (Task 8).
4. Logout while the network is down: local session must still be cleared (Task 5).
5. Missing `API_BASE_URL` (forgot `--dart-define-from-file`) fails fast with a clear message instead of a blank screen; double-tapping Submit sends one request (Tasks 3, 7).

  Future<ResponseBody> Function(RequestOptions) handler; final List<RequestOptions> requests; }

**Algorithm (binding):**
- State: `Future<String?>? _inflight`.
- `Future<String?> _refresh() => _inflight ??= _doRefresh().whenComplete(() => _inflight = null);` (single-flight: every concurrent caller awaits the same Future).
- `_doRefresh()`: read refresh token; if null -> `await tokens.expire()`, return null. Else `await refresh(rt)`; on success `await tokens.save(...)` (BEFORE returning, so the rotated token is persisted before any retry) and return the new access token. On `DioException` whose `response?.statusCode == 401` -> `await tokens.expire()`, return null. Any other failure (no response, 5xx, 429, timeout) -> rethrow without touching tokens (transient).
- `onRequest`: if `tokens.accessToken` is null, `await _refresh()`; null result -> `handler.reject` a 401 `DioException(type: badResponse, response: Response(statusCode: 401))`; a thrown transient error -> reject with it. Otherwise set `Authorization: Bearer <token>`.
- `onError`: pass through (`handler.next`) unless `statusCode == 401` and `extra['auth_retried'] != true`. Capture the sent header. If `'Bearer ${tokens.accessToken}'` differs from the sent header (another caller already refreshed), skip refresh and retry with the current token. Else `await _refresh()`: null -> `handler.next(err)` (session already expired); transient throw -> `handler.next(err)`. Retry exactly once: `dio.fetch(requestOptions.copyWith(headers: {...Authorization new}, extra: {...extra, 'auth_retried': true}))` and `handler.resolve(response)`; if the retry throws `DioException`, `handler.next` that error (no second refresh because of the flag).
- Refresh endpoint is called through the bare Dio, so the interceptor never sees it (no recursion, no exempt-path list).
